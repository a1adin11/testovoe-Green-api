# testovoe-green-api

SPA на React 19 + TypeScript + Vite.

## Запуск

```bash
yarn install
yarn dev      # дев-сервер на http://localhost:5173
yarn build    # тайпчек + production-сборка в dist/
yarn preview  # локальный просмотр production-сборки
yarn lint     # eslint
```

## Структура

Feature-Sliced Design. Слои идут сверху вниз, импортировать можно только вниз:
`app → pages → widgets → features → entities → shared`.

```
src/
  app/            — инициализация приложения
    providers/      — глобальные провайдеры (react-query и т.д.)
    router/         — дерево маршрутов и охрана по сессии
    styles/         — reset.css, variables.css (токены), global.css, mixins.scss
    App.tsx         — корневой компонент
  pages/          — страницы, собранные из виджетов и фич
  widgets/        — самостоятельные блоки страницы
  features/       — пользовательские сценарии
  entities/       — бизнес-сущности
  shared/         — переиспользуемое без привязки к домену
    ui/             — UI-кит
    api/            — транспорт: инстанс axios, обёртка request, разбор ошибок
    lib/            — хелперы, хуки
    types/          — общие типы и контракты, используемые несколькими слайсами
    config/         — константы, адреса API
  assets/icons/   — SVG-иконки
  main.tsx        — точка входа (монтирование в #root)
```

## Соглашения

- Импорты — через алиасы слоёв: `@app`, `@pages`, `@widgets`, `@features`, `@entities`,
  `@shared`, `@assets`. Есть и общий `@` → `src`. Относительные пути — только внутри одного слайса.
- Именование типов: интерфейсы с префиксом `I` (`IProps`, `ICredentials`), type-алиасы с `T`
  (`TChatMessage`, `TInstanceState`).
- Слайс наружу отдаёт себя через `index.tsx` / `index.ts`: `import { Input } from '@shared/ui/input'`.
- Стили компонентов — CSS Modules на SCSS (`Component.module.scss`). Глобальные правила и токены
  живут только в `src/app/styles`.
- Миксины из `app/styles/mixins.scss` автоматически доступны в любом `*.module.scss`
  без `@use` (подключено через `css.preprocessorOptions` в `vite.config.ts`). Например `@include hover`.
- Цвета, отступы и радиусы брать из CSS-переменных в `variables.css`, а не хардкодить.
- Иконки — SVG как React-компоненты: `import Icon from '@assets/icons/name.svg?react'` (vite-plugin-svgr).
- Формы — `react-hook-form` + `zodResolver`. Схема лежит в `model/schema.ts` слайса,
  тип значений выводится из неё через `z.infer`, руками не дублируется.
- Клиентское состояние — `zustand` (`entities/*/model/store.ts`), серверное — `@tanstack/react-query`.
- Роутинг — `@tanstack/react-router`, маршруты описаны кодом в `app/router`. Доступ к страницам
  закрывается через `beforeLoad` + `redirect`, а не проверкой внутри компонента.
- Фичи не знают о маршрутах: навигацию после действия задаёт страница через коллбэк
  (`<LoginForm onSuccess={...} />`), а не сама фича.
- Запросы к GREEN-API лежат рядом с компонентом, который их использует: функция для
  `queryFn`/`mutationFn` — в его папке `api/`, хук поверх неё — в `hooks/`. Если запрос нужен
  и дочерним компонентам, обе папки заводятся у родителя. Компоненты зовут только хуки.
- В файле ручки остаётся только сам запрос и его параметры. Контракт ответа — типы,
  zod-схемы и сужающие их гарды — лежит в папке `types/` того же компонента.
  Схема переезжает вместе с типом: тип выводится из неё через `z.infer`, так что
  разделить их значило бы получить циклический импорт.
- Типы, нужные нескольким слайсам, живут в `shared/types` (`IApiCredentials`,
  `TInstanceState`). `shared/types` ни от чего не зависит — на него можно ссылаться
  из любого слоя.
- HTTP — через `apiInstance` (axios) из `shared/api`. Напрямую `axios` или `fetch` в коде не вызываем:
  обёртка `request()` добавляет сборку пути и валидацию ответа схемой, а интерцептор
  инстанса приводит любую ошибку к `ApiError`.
- В ключ кэша входит `idInstance`, но не `apiTokenInstance`: при смене инстанса кэш
  не должен переиспользоваться, а токену нечего делать в devtools.
- Адреса API — константы в `shared/config`: они публичные и одни для всех.

## Маршруты

| Путь | Страница | Доступ |
| --- | --- | --- |
| `/` | — | редирект на `/chat` или `/login` по наличию доступов |
| `/login` | `LoginPage` | только без доступов (иначе `/chat`) |
| `/chat` | `ChatPage` | только с доступами (иначе `/login`) |

## Приём сообщений

Очередь уведомлений у GREEN-API одна на инстанс, читается long polling'ом
(`receiveNotification`, сервер держит запрос до 60 секунд) и требует явного
подтверждения через `deleteNotification`.

- Подписка живёт на уровне `ChatPage` (`hooks/useNotifications.ts`) и не зависит от
  открытого диалога: очередь общая, её нужно вычитывать постоянно.
- Цикл опроса — асинхронный генератор, обёрнутый в `experimental_streamedQuery`.
  Ошибки гасятся внутри генератора, чтобы поток не завершался.
- Подтверждать нужно **каждое** уведомление, даже неинтересное: неподтверждённое
  остаётся головой FIFO-очереди и блокирует все следующие события.
- Подтверждение идёт после записи в кэш. Обратный порядок терял бы сообщение при
  сбое между вызовами, а этот максимум продублирует — дубль снимается слиянием.
- Слияние истории и живых сообщений — по `idMessage` (`lib/mergeMessages.ts`).
  Ключ обязателен: очередь гарантирует доставку «хотя бы один раз».
## Завершение сессии

Доступы сбрасываются из трёх источников, но решение всегда одно — `logout()`:

- уведомление `stateInstanceChanged` с состоянием, отличным от `authorized` — узнаём
  о разлогине инстанса сразу, не дожидаясь отклонённого запроса (требует включённого
  `stateWebhook` в настройках инстанса);
- любой запрос, отклонённый по доступам, — `isSessionRejected` в `shared/api`
  (401, 403 и часть 400: инстанс удалён, просрочен, разлогинен). Ловится глобально
  в `QueryCache`/`MutationCache`;
- кнопка «Выйти».

Редирект на `/login` висит один, в `app/router`: подписка на стор сессии. `beforeLoad`
срабатывает только при переходах, поэтому сам по себе разрыв не закрывает — инстанс
могли разлогинить, пока пользователь сидит на странице.

Запросы с отклонёнными доступами не повторяются: `retry` проверяет `isSessionRejected`.

- Эталон форм ответов и уведомлений — официальная Postman-коллекция
  [green-api/green-api-postman-collection-telegram](https://github.com/green-api/green-api-postman-collection-telegram).
